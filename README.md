# Derealization experiment (v4)

People who have had episodes of derealization see two edited versions of
the same photograph on each trial and press ← or → to choose the one that
looks more like how their surroundings looked during **one specific
episode**. The two versions differ in local contrast (a "fog"-like
reduction), in colour saturation, or in both. A per-person model then
estimates how strongly each person's choices follow each feature:

```
P(chose A) ~ b_sat · pred_sat + b_fog · pred_fog
```

A **control group** of people who have never had such episodes does exactly
the same task, imagining how the surroundings might look to someone
experiencing derealization. The two groups differ **only in the wording**
of four things: the anchoring screen, the trial prompt, the episode-grid
question, and the word-rating instruction and question.

The design is preregistered. The stimuli, the trial order and the grid
layout come from the frozen **v4** packages in `data/sets/v4/` and are never
randomised, reordered, resampled or regenerated by the experiment.

jsPsych 7, hosted on GitHub Pages, data uploaded through DataPipe to OSF.
See `SETUP.md` for deployment and `DATA_DICTIONARY.md` for the output.

## The session

The same for both groups. About **25 minutes** (estimate; to be confirmed
by a timed run). Each step has its own switch in `config.js`.

| # | step | switch |
|---|---|---|
| 1 | Consent — "I do not agree" ends the session, nothing uploaded | `blocks.consent` (**required** on `index.html`) |
| 2 | Full screen and window check — a window that cannot show the trial layout whole **stops** the session (no "continue anyway"), before anything is uploaded | `calibration.fullscreen`, `calibration.screen_check` |
| 3 | Participant ID (+ optional name and email, uploaded separately straight away) | `participant.collect_*` |
| 4 | Brightness confirmation, with a note on night mode / colour filters | `calibration.brightness` |
| 5 | Gamma matching (3×) | `calibration.gamma` |
| 6 | Anchoring — one specific episode (participants) / what derealization is (controls) | `blocks.anchoring` |
| 7 | Practice — 6 trials | `blocks.practice` |
| 8 | Pair trials — 205, with 4 breaks (every 41) | `blocks.main` |
| 9 | Episode grid block — 4 screens, with "None of these" and optional free text | `blocks.grid_episode` (+ `blocks.grid_none_text`) |
| 10 | Word ratings — 10 words, 0–6 | `blocks.words` |
| 11 | Normal-appearance grid block — 4 screens | `blocks.grid_normal` |
| 12 | State items — 4 items, 0–6 (optional block) | `blocks.state` |
| 13 | Save, completion screen | `platform` |

The images (≈150 MB) start downloading in the background right after the
ID screen, so they are usually cached by the time the practice needs them.

## Invitation links

Each participant gets their own link. All parameters are read in the
browser and never reach the server.

```
https://<username>.github.io/<repo-name>/?pid=<ID>&group=<group>&idate=<YYYY-MM-DD>
```

| parameter | required | values | notes |
|---|---|---|---|
| `pid` | yes* | `R_` + 15 letters/digits, case-sensitive | *if missing, the participant may type it (`participant.allow_manual_id`) |
| `group` | **yes** | `participant` or `control` (exact, lower case) | missing or misspelt → the study does not start and shows "This link is incomplete" |
| `idate` | no | `YYYY-MM-DD`, a real date | the interview date, added by the researcher who schedules the interviews. Never asked on screen. Invalid → recorded empty |
| `lang` | no | `en` (default) or `ja` | |

Examples:

```
.../?pid=R_9rJJWk01c767jE8&group=participant&idate=2026-11-03
.../?pid=R_4EWNe48BIB50mVI&group=control&lang=ja
```

Building them from a table (Python):

```python
from urllib.parse import urlencode
BASE = 'https://<username>.github.io/<repo-name>/'
def link(pid, group, idate=None, lang=None):
    assert group in ('participant', 'control')
    q = {'pid': pid, 'group': group}
    if idate: q['idate'] = idate          # 'YYYY-MM-DD'
    if lang:  q['lang']  = lang
    return BASE + '?' + urlencode(q)
```

See `SETUP.md` §6 for what to put in the invitation email.

## Things worth knowing

**The packages are frozen.** `data/sets/v4/` and `data/sets/v4/grid/` are
byte-identical copies of the archived originals in
`drl2drv_updated/data_trials/` (see `SETUP.md` §5 for the check). Never
edit, re-encode, resize or rename anything in them.

**`pair_type`, not `trial_type`.** jsPsych writes its own `trial_type` column
holding the plugin name. The design label from `trial_list.json` is renamed
to `pair_type` on output so the two do not collide. Analyse on `pair_type`.

**Only the side is recorded.** Each row stores `response_side` as `left` or
`right`. Mapping that to "chose A" via `a_is_left` happens in the analysis
script, not in the browser, so the conversion can be inspected.

**The background is mid-grey.** The manipulations are colour saturation and
local contrast. A white surround would shift the participant's adaptation
state toward the bright end and compress the differences under study.

**Images are always 512 × 512 CSS pixels** (`display.allow_scaling: false`).
That is why the window check stops, rather than warns, when they do not fit.

## Settings you are most likely to change

In `config.js`:

| Setting | Purpose |
|---|---|
| `platform` | `'local'` / `'github'` / `'pavlovia'` |
| `debug` | validation report in the console; upload details on the completion screen |
| `blocks.*` | each step on or off (see the session table) |
| `participant.allow_manual_id` | set false to require the URL parameter |
| `researcher_contact` | shown on the final and upload-failure screens |
| `timing.break_every` | 41 = five equal parts of the 205 pair trials |

The wording lives in `text/en/` and `text/ja/`. Group-dependent strings are
objects keyed `participant` / `control`.

## Developer page

Open `dev.html` (e.g. `http://localhost:8000/dev.html`). Choose a **group**
first (chips at the top; the presets stay disabled until one is chosen),
optionally a language and a fixed `set_code`, then a preset or a custom
session with any combination of block switches. Every dev session is
stamped `is_dev = true`. All presets except "Upload test" save locally
instead of uploading.

this list on the exact commit you deploy, and **do not send a single
invitation while any item fails**.
